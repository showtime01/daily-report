# 営業日報システム — テスト仕様書

---

## 1. テスト概要

### 1-1. 目的

本仕様書は、営業日報システムの品質を保証するために実施するテストの範囲・手順・合否判定基準を定義する。
API仕様書（`doc/API_SCHEMA.md`）・画面設計書（`doc/SCREEN_DESIGN.md`）・ER図（`doc/ER_DIAGRAM.md`）に記載された要件を満たすことを確認する。

### 1-2. テスト範囲

| 対象 | 範囲 |
|------|------|
| 認証 | ログイン・ログアウト・セッション管理・ロール制御 |
| 日報 | CRUD・ステータス遷移（draft → submitted → reviewed） |
| 訪問記録 | CRUD・日報との連動 |
| コメント | 投稿・取得・ロール制限 |
| ユーザーマスタ | CRUD・論理削除 |
| 顧客マスタ | CRUD・論理削除・担当営業管理 |

以下はテスト範囲外とする。

- パフォーマンス・負荷テスト
- セキュリティ診断（ペネトレーションテスト）
- ブラウザ互換性テスト

### 1-3. テストレベル

| レベル | 説明 | 本仕様書での位置づけ |
|--------|------|-------------------|
| 単体テスト | 各APIエンドポイントの個別動作確認 | **本仕様書の主対象** |
| 結合テスト | 複数エンドポイントをまたぐシナリオ確認 | 第5章に記載 |
| E2Eテスト | ブラウザ操作による画面フロー確認 | 将来対応（別紙） |

## 7. 合否判定基準

| 基準 | 内容 |
|------|------|
| 単体テスト | 全テストケースがパスすること |
| 結合テスト | TC-INT-001〜005 が全ステップでパスすること |
| エラーコード | レスポンスの `error.code` が仕様書定義値と一致すること |
| バリデーション | `details[].field` が対象フィールド名と一致すること |
| データ永続化 | 作成・更新・削除後に `GET` で状態が反映されること |
| ロール制御 | 権限外操作に対して必ず `403` が返ること |
